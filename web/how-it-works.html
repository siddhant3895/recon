Engine Specification

The 4-Tier Matching Cascade

Recon matches financial records deterministically without opaque generative models. Both sides pass through an identical normalization pipeline before entering an ordered cascade.

1. Deterministic Normalizer (normalizer_v1)

Bank statements and client ledgers write the same transaction in wildly different formats. The normalizer applies eight mathematical transformation steps:

  1. Unicode NFKC & Whitespace Collapse: Standardizes character encodings and removes erratic bank spacing.
  2. Case Normalization: Lowercase transformation across all text fields.
  3. Indian Banking Boilerplate Stripping: Removes repetitive bank prefixes: NEFT/, RTGS/, IMPS/, UPI/, CHQ/, CLG/, ATM/, POS/, ACH/, TO , FROM , BY , REF , TRF .
  4. Reference Token Extraction: Long digit sequences (≥8 digits like UTRs and cheque numbers) are extracted and indexed as ref_token, leaving only meaningful party names in the narration text.
  5. Punctuation Sanitization: Removes non-alphanumeric noise while strictly preserving decimal points and currency amounts.
  6. Integer Paise Conversion: Eliminates floating-point rounding bugs by storing every rupee as an integer number of paise (₹1,500.50 → 150050 paise).
  7. Ambiguous Date Widening: When day and month are both ≤12 (e.g. 05/06/2026), Recon flags the row as date-ambiguous and widens the search window to ±30 days rather than guessing.
  8. Direction Verification: Identifies debit vs credit to prevent improper offsetting.

2. Non-Negotiable Hard Gates

Before any candidate pair is scored, it must clear three hard mathematical gates. If any gate fails, the candidate is discarded immediately:

  • Direction Gate: Debits only match debits; credits only match credits. Cross-direction pairing is strictly forbidden.
  • Amount Tolerance Gate: Delta must fall within the tier's strict threshold (exact in Tiers 1–2; ±2% in Tier 3; ±₹1 or ±0.5% in Tier 4).
  • Date Window Gate: Transaction dates must be within the tier's calendar boundary (same day for Tier 1; ±3d for Tier 2; ±30d for Tier 3; ±10d for Tier 4).

3. The 4-Tier Matching Cascade

Tier Criteria & Search Conditions Max Candidates
Tier 1: Exact Identical amount (paise) + identical date + exact ref_token (UTR/IMPS/Cheque). All exact matches
Tier 2: Fuzzy Reference Identical amount + date within ±3 days + Jaro-Winkler reference similarity ≥ 0.85 (handles single-digit OCR/typo errors in UTRs). Up to 5
Tier 3: Narration Band Amount within ±2% + date within ±30 days + narration token-set ratio ≥ 0.60 (tolerates small amount differences like bank charges, and missing UTRs). Up to 3
Tier 4: Subset-Sum Many-to-one: 1 bank statement line vs 2–4 ledger entries. Total sum within ±₹1 or ±0.5%, date within ±10 days. Bounded DFS with 5,000 node ceiling and deterministic abandonment path. Up to 3 sets
