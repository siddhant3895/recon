Security, Data Residency & Retention

CA firms handle confidential client financial ledgers and bank accounts. Our security model is designed to withstand strict partner audit and compliance scrutiny.

Security Overview at a Glance

Geographic Location AWS ap-south-1 (Mumbai, India). Financial data never leaves the Republic of India. No US or European transit.
Encryption at Rest AES-256. Every storage object encrypted with per-firm KMS keys.
Encryption in Transit TLS 1.3 everywhere. Plain HTTP and weak cipher suites are strictly prohibited and dropped.
Tenant Isolation PostgreSQL Row-Level Security (RLS). Firm ID is the root boundary on all tables. Cross-firm ID queries return 404.
Retention & Purge 30-Day Hard Purge. Raw bank PDFs and CSV uploads are destroyed automatically 30 days after run completion.
Audit Logging Append-Only. Every match decision, export, login, and purge event writes an immutable audit record with actor ID and timestamp.
Contractual Protection DPA & NDA. Co-signed by legal guardian. DPDP Act (India) compliant data processing terms.

1. Indian Data Residency (AWS ap-south-1)

Many generic SaaS tools route client documents through foreign inference APIs or US-based cloud regions. Recon is built with strict regional containment:

  • Object storage is hosted exclusively in AWS Mumbai (ap-south-1).
  • PostgreSQL databases run in Supabase Mumbai / RDS Mumbai.
  • Matching workers run on isolated Indian compute nodes.
  • No LLM in the matching loop: documents are parsed and scored using local, deterministic Python mathematics, not forwarded to third-party AI APIs.

2. Automated 30-Day Raw File Purge

Firms frequently ask: "Why do you need to keep my bank statement after the reconciliation is finished?" We don't.

  • Upon upload, a purge_after timestamp is attached (exactly 30 days from processing).
  • A daily scheduled retention worker unlinks and permanently shreds raw PDF and CSV file objects.
  • The purge operation generates an immutable audit entry recording the bytes freed, the firm ID, and the timestamp.
  • Only normalized metadata and human match decisions remain for your reconciliation history.

3. Tenant Boundary & Postgres RLS

Every database query runs under PostgreSQL Row-Level Security. There is no shared cross-tenant workspace. If a user or malicious script attempts to access another firm's upload ID or statement line, the database engine returns 0 rows (404 Not Found), verified by continuous automated regression tests.

4. Incident Disclosure & Legal Protection

In the unlikely event of any security anomaly:

  • 72-Hour Disclosure: All affected account owners receive direct email notification within 72 hours of verification.
  • Named Point of Contact: Dedicated security email and emergency phone escalation for subscribed firms.
  • Guardian Co-Signature: Because the principal software architect is a minor, all Data Processing Agreements (DPAs) and Non-Disclosure Agreements (NDAs) are co-signed by an adult legal guardian, ensuring 100% legal enforceability under Indian contract law.
